Roadmap

Where P4sim is heading

P4sim grows release by release. Each release below lists its main features; the issues and pull requests on GitHub have the details.

  • Released
  • In progress
  • Planned
  • Ideas
  1. v1.0 Released June 2025

    First public release

    • BMv2 P4 switches inside ns-3, with the V1model, PSA and PNA architectures.
    • Bridge-based switch design (Arch 1): each port is an ns-3 CSMA or point-to-point device.
    • Examples and topology helpers, from tunnels and a firewall to spine-leaf and fat-tree networks.
    • Described in the ICNS3 2025 paper, with a reproducibility artifact.

    Release v1.0.0 · Artifact

  2. v1.1 In progress mostly on main

    Stability and control plane

    • Runtime control plane: P4Controller manages table entries, action profiles and more while a simulation runs (GSoC 2025).
    • Fixes: PNA forwards packets, switch cores are released cleanly, broken examples work again.
    • Testing: seven test suites, packet tests on all three architectures, and smoke tests for the examples.
    • V1model like simple_switch: priority queues done; resubmit, recirculate, clone and digest in progress.
    • Faster, parallel runs: configurable BMv2 log level and automatic Thrift ports.

    Changes on main since v1.0.0

  3. v1.2 In progress

    Newer ns-3

    • ns-3.49 (C++23), maintained next to the ns-3.39 line.
    • BMv2's C++20 build fix sent upstream, so installation needs no manual header patch.
    • Easier builds, without hard-coded library paths.

    ns-3.49 branch

  4. v2.0 Planned

    Switch-centric architecture

    • Arch 2: ports belong to the switch and connect through a switched Ethernet channel.
    • Traffic manager: virtual output queues, priority scheduling and event-driven egress.
    • A queue timing model.
    • Automatic processing rate, with no idle polling.

    switch_channel branch (in development)

  5. Later Ideas

    Under consideration

    • Per-table counters and richer tracing.
    • Faster simulations, for example with the BMv2 log off by default.
    • More example scenarios.
