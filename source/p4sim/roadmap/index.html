Roadmap

Where P4sim is heading

P4sim grows release by release. Each release below lists its main features; the issues and pull requests on GitHub have the details.

  1. v1.0 Released June 2025

    First public release

    • BMv2 P4 switches inside ns-3, with the V1model, PSA and PNA architectures.
    • Bridge ports: each port is an ns-3 CSMA or point-to-point device.
    • Examples and topology helpers, from tunnels and a firewall to spine-leaf and fat-tree networks.
    • Described in the ICNS3 2025 paper, with a reproducibility artifact.
    • The 1.x line stays in the branch main-deprecated, which gets no more changes.

    Release v1.0.0 · Artifact

  2. v2.0 Released November 2026

    Ports and timing

    • Switched-Ethernet ports: a switch can own full-duplex SwitchedEthernetChannel ports with plain host devices. Bridge ports still work, and both kinds can be mixed.
    • Timing: event-driven egress for V1model, PSA and PNA, so a congested port sends back to back at its line rate; exact serialisation and optional Ethernet framing. PipelineDelay gives the pipeline a latency, and SwitchRate limits the packet rate of the whole pipeline.
    • Traffic manager (EnableVoqFabric, V1model): virtual output queues, a fabric scheduler and strict-priority egress queues.
    • Control plane: simple_switch_CLI and psa_switch_CLI work with the simulated switches; mirroring, clones, digest() and LAG; P4Controller (GSoC 2025) manages flow entries, action profiles and mirroring sessions; EnableSwap swaps the program at run time.
    • Easier use: no P4SIM_DIR, automatic Thrift ports, the BMv2 log off by default, and a Docker image with the tested setup.
    • Tests: 18 test suites (1.0 had 6), packet tests in the style of p4c's STF, and 23 examples that run as tests.
    • Breaking changes: SwitchRate defaults to 0 (no limit) instead of 1000 packets per second, so throughput and delay differ from 1.x; ChannelType and EnableTracing have no effect; the waf build is gone.

    Release v2.0.0 · Changes since v1.0.0

  3. Next In progress on main

    Newer ns-3 and a fuller control plane

    • ns-3.39 to ns-3.49 from one code base, tested with ns-3.39 and ns-3.49. P4sim builds with a fixed copy of BMv2's spdlog headers, so no manual patch is needed.
    • Transfer buffer (TransferBufferSize): the hardware port queue after the egress pipeline.
    • Digests in the simulation: a Digest trace source and a P4Controller callback; the example p4-l2-learning learns its tables from them.
    • P4Controller on every architecture, through the new P4RuntimeApi; errors in a flow table are reported with file and line.
    • PNA honours PipelineDelay and loads its flow table with bm_CLI; new examples p4-priority-queues and p4-latency.
    • Getting started: install.sh sets up everything in about 6 minutes on 16 cores; p4-hello and a getting-started guide; every example checks its own result.

    Changes on main since v2.0.0

  4. Later Planned

    Closing the gaps

    • PSA externs for PSA and PNA programs (pull request #102, in review).
    • Pipeline core: multicast, clones, resubmit and recirculation, with the packet replication engine of V1model.
    • BMv2: fixes for upstream, an optimised build, and finding BMv2 through CMake.
  5. Ideas Ideas

    Under consideration

    • Cut-through forwarding, which changes the latency but not the throughput.
    • A timing model per pipeline stage.
    • A default size for the transfer buffer, and the transfer buffer with the VOQ traffic manager.
