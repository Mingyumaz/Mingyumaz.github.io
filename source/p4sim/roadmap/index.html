Roadmap

Where P4sim is heading

P4sim grows release by release. Each release below lists its main features; the issues and pull requests on GitHub have the details.

  1. v1.0 Released June 2025

    First public release

    • BMv2 P4 switches inside ns-3, with the V1model, PSA and PNA architectures.
    • Bridge ports: each port is an ns-3 CSMA or point-to-point device.
    • Examples and topology helpers, from tunnels and a firewall to spine-leaf and fat-tree networks.
    • Described in the ICNS3 2025 paper, with a reproducibility artifact.
    • The 1.x line stays in the branch main-deprecated, which gets no more changes.

    Release v1.0.0 · Artifact

  2. v2.0 Released November 2026

    Ports and timing

    • Switched-Ethernet ports: a switch can own full-duplex SwitchedEthernetChannel ports with plain host devices. Bridge ports still work, and both kinds can be mixed.
    • Timing: event-driven egress for V1model, PSA and PNA, so a congested port sends back to back at its line rate; exact serialisation and optional Ethernet framing. PipelineDelay gives the pipeline a latency, and SwitchRate limits the packet rate of the whole pipeline.
    • Traffic manager (EnableVoqFabric, V1model): virtual output queues, a fabric scheduler and strict-priority egress queues.
    • Control plane: simple_switch_CLI and psa_switch_CLI work with the simulated switches; mirroring, clones, digest() and LAG; P4Controller (GSoC 2025) manages flow entries, action profiles and mirroring sessions; EnableSwap swaps the program at run time.
    • Easier use: no P4SIM_DIR, automatic Thrift ports, the BMv2 log off by default, and a Docker image with the tested setup.
    • Tests: 18 test suites (1.0 had 6), packet tests in the style of p4c's STF, and 23 examples that run as tests.
    • Breaking changes: SwitchRate defaults to 0 (no limit) instead of 1000 packets per second, so throughput and delay differ from 1.x; ChannelType and EnableTracing have no effect; the waf build is gone.

    Release v2.0.0 · Changes since v1.0.0

  3. v2.1 Released November 2026

    Newer ns-3, externs and a control plane for every architecture

    • ns-3.39 to ns-3.49 from one code base, from C++17 to C++23; CI builds and tests ns-3.39 and ns-3.49. P4sim carries a fixed copy of BMv2's spdlog headers, so no manual patch is needed.
    • PSA and PNA externs: Counter, Meter, Hash, InternetChecksum and Random. Before, a program that used one of them failed to load.
    • Control plane on every architecture: the new P4RuntimeApi makes the BMv2 runtime calls, and P4Controller works on V1model, PSA and PNA switches. digest() records reach the simulation through the Digest trace source and a P4Controller callback; p4-l2-learning learns from them.
    • Transfer buffer (TransferBufferSize, V1model and PSA): the hardware port queue after the egress pipeline. The default, 0, keeps the 2.0 behaviour.
    • Reproducible runs: meter.execute_meter() and the PSA and PNA Meter count simulation time instead of the wall clock; random() and the PSA Random draw from an engine per switch, seeded from the ns-3 seed and run number.
    • Getting started: install.sh sets up everything on Ubuntu 24.04 or 26.04 in about 6 minutes on 16 cores; p4-hello and a getting-started guide.
    • Examples: 32 (2.0 had 23), and each checks its own result. New are p4-hello, the p4lang tutorials ecn, mri and multicast, a PSA policer, PSA ECMP, priority queues, L2 learning and p4-latency.
    • Tests: 21 test suites with 167 cases (2.0: 18 with 113). Of p4c's 221 BMv2 test programs, 154 give the same output on P4sim as on BMv2.
    • Fixes: three crashes found with p4c's test programs, the ingress port of hosts on switched-Ethernet ports, and a crash at the end of every simulation on Ubuntu 26.04.
    • Documentation and license: a new architecture figure in the README, which draw.io edits. P4sim's own code is Apache-2.0; files derived from ns-3 and other GPL code stay GPL-2.0-only.
    • Changed interface: the runtime calls of P4CoreV1model moved to P4RuntimeApi, with the same names and arguments. Simulations that use P4Controller, the helpers or flow-table files need no change. Results can differ from 2.0 where 2.0 was wrong or not reproducible: the ingress port of hosts on switched-Ethernet ports, meter colors and random numbers.

    Release v2.1.0 · Changes since v2.0.0

  4. Next In progress in review

    Target profiles: the latency of real switches

    • Target profiles (TargetProfile): JSON files that give a switch the timing of a real target, kept apart from the P4 program. Without a profile nothing changes.
    • tofino-like: a per-packet latency that depends on the headers a packet parses and the tables it matches (Franco et al., 2024), plus the MAC and egress delays (DPTP, SOSR 2019).
    • cut-through-reference: a cut-through switch without buffers, which starts to send a frame before its last bit has arrived.
    • Learning tables filled from the program's digests, with a capacity, replacement of the oldest entry and aging, learned in the data plane or through the control plane with a delay.

    Pull request #114 · Changes on main since v2.1.0

  5. Later Planned

    Closing the gaps

    • Pipeline core: multicast, clones, resubmit and recirculation, with the packet replication engine of V1model.
    • Direct meters of V1model on simulation time; BMv2 runs them with the wall clock.
    • BMv2: fixes for upstream, an optimised build, and finding BMv2 through CMake.
  6. Ideas Ideas

    Under consideration

    • A default size for the transfer buffer, and the transfer buffer with the VOQ traffic manager.
    • PSA DirectCounter and DirectMeter, and a Counter in PNA programs, once p4c compiles them for BMv2.
    • A drop port that can be set, and a mirroring session with both a port and a multicast group.
